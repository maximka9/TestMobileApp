# SASAclicker 0.5 content and persistence

## Public streamer snapshot

`resources/streamers/streamers.json` contains 473 unique public channel names
observed on 2026-09-08. The 0.5.1 specification explicitly permits a documented
400+ target; **400+ verified profiles is now the canonical production requirement**.
Each entry includes its exact source page, observation date, measured average
viewers and `is_placeholder: false`.

Sources: [Russian rankings](https://twitchtracker.com/channels/ranking/russian),
[Russian follower rankings](https://twitchtracker.com/channels/most-followers/russian).
The URLs in individual records identify the actual pagination used. These are
observations from the available public snapshot, not continuously current stats.
Missing average-viewer values were omitted instead of invented. Names were
deduplicated case-insensitively. Unverified interests remain empty.
Acceptance probabilities, relationship scores and available collaboration
formats are fictional game parameters, not claims about these people.

The old fictional 500-record catalog lives only in `tests/fixtures`, excluded
from exports. Old saved relationship IDs remain preserved but do not become
production collaboration profiles.

`tools/import_streamers.py` is a developer-only alternative based on the official
[Twitch Get Streams API](https://dev.twitch.tv/docs/api/reference/#get-streams).
Set `TWITCH_CLIENT_ID` and `TWITCH_APP_TOKEN` locally, then run:

```powershell
python tools/import_streamers.py --previous resources/streamers/streamers.json --output build/streamers-review.json
```

Review that file before replacing production data. The importer follows cursors,
deduplicates channels, stops at 500 or the end of available live streams, and
never pads the result. This API returns current live viewers, not an average;
`reach_basis: live_snapshot` records that distinction. It infers a topic only
from the observed game category. Tokens are neither written nor printed.
Live API execution was not performed; offline pagination tests cover the tool.
The game never connects to Twitch or sends messages.

0.5.1 adds platform, login and platform_user_id fields. Public ranking pages do
not provide reliable Twitch user IDs, so existing external IDs remain empty;
they are not fabricated from logins. The Helix importer now captures actual
`user_id` values. Game IDs and saved relationship keys remain unchanged until
verified external IDs are available. Duplicate known external IDs and
case-insensitive logins are rejected. A future nickname change must preserve the
game ID; `--previous` matches the external ID and retains the prior game key even
when the login changes. New verified profiles use `twitch:<user_id>` as game key.
Legacy entries gain their external IDs through a login match. No live-ID migration
was performed without authenticated Helix data.

## Gameplay and save schema 9

- Hype >=95 awards x1.15 click XP, evaluated before the click's hype gain.
  Fractional XP accumulates during the session; summary displays awarded XP.
  Direct progression rewards do not receive this multiplier.
- Completed streams create one matching, single-use content source. An accepted
  FAIL creates an additional fail source. Rejected publications preserve sources;
  successful publication spends one, irrespective of its viral outcome.
- Sources retain unique IDs, originating stream, topic, time and consumed state.
  The archive is bounded to 4096 records, discarding consumed entries first and
  then the oldest available entry if all are unconsumed.
- Offline fatigue recovers by two points per full minute. Partial seconds survive
  save/reload; starting a stream resets the recovery remainder. The existing
  offline cap and interrupted-stream exclusion remain in effect.
- Hype and target-viewer fatigue curves are separate GameConfig values. Existing
  fractional viewer smoothing is retained. No UI code subtracts online viewers.
- Schema 1–8 saves migrate without inventing content sources. Unknown/unavailable
  location scenes fall back to the room; other career progress remains intact.

Location selection is a service command. The controller replaces the single
child of LocationContainer and closes the selector. City remains disabled SOON.
Cooking requires Kitchen. Career appearance is shared data for both scenes.

Achievements use Resource parent IDs, positions and tiers. The graph shows
completion and connections, while tapping a node shows its goal and progress.
The existing achievement evaluation rules are preserved.
