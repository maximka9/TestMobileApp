# 0.8 targeted audit

Base: clean main / v0.7.0, 7f0c23ab9b3661cf56b49e07818299b9d707656e.
One agent and one temporary branch: feature/progression-balance.

| Issue | Cause | Fix | Regression test |
|---|---|---|---|
| Increasing physical XP grind | Power threshold, almost fixed click XP | Linear threshold, level XP, capped equipment multiplier | Level 1/5/10/20, 100 physical clicks, high-hype boundaries |
| Level feels abstract | No click mastery, no level in header | Configured mastery, visible level, data-driven required_level guards | Mastery growth/cap, content/upgrade/move/cosplay restrictions |
| Fake +hype at MAX | click() returns potential gain instead of applied delta | Return actual hype, integer XP and level transition; reuse pool | 98->100 delta 2, MAX only XP, fixed pool size |
| Foreground monitor hides feedback | Monitor has higher draw order than Effects | Pool z-index above room objects | Final rendered click screenshots |
| Slow discontinuous recovery | 2 per whole real minute | 10/min float elapsed recovery; existing monotonic tick drives UI | Fractional intervals, call frequency, offline parity/cap, live guard |
| Pre-stream cosplay | StreamService charges and applies costume in start() | MoveService activation, once per stream, existing tags/costs/novelty | Offline rejection, first/second/new session, clear after finish |
| Contradictory summary online | Green banner reads career average; rows read session average | Remove duplicate career statistic; shared StreamSessionStats | Samples 2/4/8/6, peak 10 with unrelated hype/career 24.1, idempotency |
| Legacy XP thresholds differ | Existing schema stores absolute XP within level | Schema 11 migrates ratio once without changing level | Multiple levels/progress ratios and repeated roundtrip |

No separate FatigueService or StreamSessionStats existed. Foreground timing in 0.7
already uses monotonic real time, so no time-loop rewrite was necessary.
The stream/upgrade/action/cosplay definitions had no required_level field; added
compatible default 1 with domain guards rather than hardcoded UI unlocks. Existing
location.required_level is retained. XP still does not directly award followers.

Cosplay data has starter_cosplay as sprite_variant, but no corresponding texture
exists. Optional mapped existing textures are supported; normal identity remains
when no texture is supplied. No new artwork or external assets were generated.
