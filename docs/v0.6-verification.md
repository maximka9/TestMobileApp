## Explicitly changed test contracts

- Ordinary completed streams create usable content material and record history;
  they do not mint followers. Content and completed collaborations award followers.
- Viewer smoothing converges to the current configured target within rounding
  tolerance, rather than the obsolete fixed 17-viewer expectation.
- The baseline tail is bounded by audience_soft_cap; final modifiers have their
  own configured cap. Neutral 100 followers = 4, neutral 2M = 12000.
- Collaboration viewer momentum is separate from viral growth momentum and
  decays over three streams. Viral momentum still improves request probability.
- Cached candidates remain stable until refresh. Catalog/scale changes in legacy
  fixtures must expire the cache before expecting a new selection.
- Main navigation retains four entries; the primary action opens stream selection.

## State and catalog

Schema 10 adds candidate IDs/deadline/recent history, an expiring incoming invite,
next invite check time, collaboration boost/remaining streams and curve version.
Schema 9 migration preserves followers, XP, relationships, achievements, sources,
locations and fatigue. Long absence triggers one refresh, never a catch-up loop.

Invites can arrive during an active stream (hype affects probability); accept or
decline between streams. Acceptance costs fatigue, zero coins, and no immediate
follower reward. A matching stream lasting at least 30 seconds completes it once.
The 20-minute expiration and all timing/balance values are configurable.

The local directory adapter serves the existing 473 verified profiles. UI and
collaboration logic request profiles through the service/repository boundary.
The snapshot contains observed average viewers, not verified follower totals;
size labels explicitly say they are based on online audience. No invented follower
counts, runtime Twitch requests or client secrets. Game curve anchors are balance
settings, not universal claims about real creators.
